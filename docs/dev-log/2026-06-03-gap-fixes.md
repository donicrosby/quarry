# Dev log — 2026-06-03 (gap fixes)

## Session summary

Follow-on to the Week 11 session. Fixed gaps 2 and 3 from the initial ship.

## Gap 2 — `--focus` wired server-side

**Root cause:** `focus_classes` was resolved in the CLI (`resolve_focus`) and passed
to `_run_scan_command` but then dropped: `client.start_scan(repo_path, target_url)`
had no `vuln_classes` parameter.

**Fix — seven-file chain, bottom-up:**

1. `local_scan_profile` gains `vuln_classes: list[VulnerabilityClass] | None = None`;
   overrides the default when provided. Default **expanded** to include
   `COMMAND_INJECTION` (CMDI was already running without a gate; now the gate and
   the default are consistent).
2. `RunScanInput.vuln_classes: list[VulnerabilityClass]` added (empty = defaults).
3. `RunScanWorkflow._run` passes `scan_input.vuln_classes or None` to
   `local_scan_profile`.
4. Scan stages (SECRETS, IDOR, CMDI) each gate on
   `VulnerabilityClass.X in scan.profile.vuln_classes` using `elif` so a skipped
   class is a true no-op, not an empty scan.
5. `StartScanRequest.vuln_classes` added to the server schema.
6. Scan router threads `body.vuln_classes` into `RunScanInput`.
7. `QuarryClient.start_scan` gains `vuln_classes` param; serialises to string values.
8. CLI `_run_scan_command` passes `focus_classes` into `client.start_scan`.

## Gap 3 — `ArchitectureDoc` persistence

**Root cause:** `ReconWorkflow.run` returned the doc but had no `db_path` and never
called the persist activity.

**Fix — four files:**

1. `ArchitectureDocRecord(Base)` added to `repositories.py` (mirror of
   `ScanManifestRecord`; `session.merge` for idempotency).
2. `save_architecture_doc` + `load_architecture_doc` added to `QuarryRepository`.
3. `"save_architecture_doc"` and `"load_architecture_doc"` cases added to the
   `match` dispatcher in `persist_scan_state`.
4. `ReconWorkflow.run` gains `db_path: str = ".quarry/quarry.db"` and calls
   `persist-scan-state` with `operation="save_architecture_doc"` after synthesis.
