### Sandbox runner fix

Running `quarry benchmark local` against a live server surfaced a pre-existing
determinism bug: `RunScanWorkflow._run` calls `secret_match_to_candidate_finding`
directly, and that constructor called `utc_now()` (`datetime.now()`), which
Temporal's sandboxed runner forbids inside a workflow. The integration tests
never caught it because the worker fixture used `UnsandboxedWorkflowRunner`.

- Parameterized `secret_match_to_candidate_finding(..., created_at=...)`; the
  workflow now passes `workflow.now()`. Direct callers still default to
  `utc_now()`.
- Switched the `temporal_worker` fixture to the default sandboxed runner so the
  tests match the production server, making the e2e/diff/cancel/resume workflow
  tests real regression coverage for sandbox violations.
- Moved `PingWorkflow`/`PingInput` out of `conftest.py` into
  `tests/ping_workflow.py` so the sandbox can reimport the workflow module
  without pulling in pytest machinery.
- Registered `build_coverage_ledger_activity` in the server worker
  (`src/quarry_server/app.py`) — it had been added to the standalone worker and
  test fixture but missed in the server lifespan, so a live server scan would
  have failed at the COVERAGE stage.
