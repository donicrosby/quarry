# 2026-06-01 Dev Log — Session 4

## Goal

Introduce the LLM safely behind a mockable interface: prompt-injection hardening
(treat all target content as inert evidence) and a `ModelClient` with mock and
LiteLLM adapters. Standalone package; not wired into the scan workflow yet.

## Changed

- Added `src/quarry_models/` package:
  - `redaction.py` — the single scrubber chokepoint; replaces secrets
    (GitHub/Slack/AWS/PEM/auth tokens + assignment-style secrets) with stable
    `[REDACTED_SECRET_N]` placeholders, with a consistency pass so a value
    redacted once never reappears in the clear.
  - `prompting.py` — `build_prompt` separates system/task/evidence/output;
    evidence is scrubbed and wrapped in `<target_content>` with a fixed
    "not instructions" note. Deterministic `prompt_hash`.
  - `validation.py` — `parse_and_validate_output` parses model output into a
    typed schema and rejects unauthorized actions (deny-by-default per role),
    schema mismatches, and leaked secrets.
  - `types.py` — `ModelMessage`, `ModelRequest`, `ModelResponse[T]` (PEP 695
    generic), `BudgetSpec`, policies, `PromptRetention`.
  - `panel.py` — recommended OSS role→(provider, model, rpm) panel + `resolve`.
  - `client.py` — sync `ModelClient` protocol + provenance/usage/cost helpers.
  - `mock_client.py` — `MockModelClient` (what all tests use).
  - `litellm_client.py` — the **only** place LiteLLM is imported; sync
    `litellm.completion`, token normalization across OpenAI/Anthropic shapes,
    `temperature=0.0`.
- `src/quarry/schemas.py` — added `ModelInvocation` and `BudgetPolicy`.
- `src/quarry/config.py` — `default_provider`, `default_model`,
  `prompt_retention` (default `metadata_only`), `redaction_enabled`
  (names avoid pydantic's protected `model_` prefix).
- `pyproject.toml` — added `litellm`; registered `quarry_models` in the build
  module list; excluded `tests/fixtures` from ruff and pyright (the
  prompt-injection fixtures are intentionally malicious/ill-typed).
- Fixtures `tests/fixtures/prompt-injection/` + golden
  `expected_sanitized_prompt.txt`.
- Tests: `test_redaction.py`, `test_prompting.py`,
  `test_model_output_validation.py`, `test_mock_model_client.py`,
  `test_litellm_client.py`, `test_model_schemas.py`, golden
  `test_prompt_injection.py`.

## Works

- Malicious fixtures stay inside the `<target_content>` evidence block; the
  instruction block is identical regardless of evidence content.
- Secrets are redacted before any prompt is built.
- Model output that proposes unauthorized actions or leaks secrets is rejected.
- Mock and (mocked) LiteLLM clients return parsed typed responses and record
  `ModelInvocation` provenance — no API keys, no network.

## Broken or questionable

- Not wired into `RunScanWorkflow` yet (intentional — real LLM findings are a
  later milestone). Budget enforcement, rate limiting, the `quarry-model` queue,
  and prompt caching are deferred to scale work.

## Open decisions

- `ModelClient` is sync to match Quarry's sync-activity rule (diverges from the
  design doc's async signature); LiteLLM uses `litellm.completion`.
- Redaction prefers over-redaction (scrub a known secret everywhere) over
  leaking — context loss is acceptable; sending raw secrets to hosted models is
  not.
